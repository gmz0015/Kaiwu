# 本地工具验收操作单

本操作单定义手动步骤与通过标准；实际执行结果只追加到 [验证记录](VALIDATION.md)，阶段勾选在 [路线图](ROADMAP.md)。构建、服务测试和界面交互分别记录，不能互相替代。

2026-10-13 用户安排：手动项目在后续实际使用中逐步验收。本单作为遇到对应场景或问题时的参考，不要求现在逐项执行或集中提交结果；尚未实际覆盖的项目继续保留未测状态。

## 专项复现前准备

1. 在待验收分支执行 `git rev-parse HEAD`，记录提交及未提交修改、macOS、芯片和工具链版本；需要重新验证变更时执行 `make check-all`，再用 `make run` 启动该分支的开发包；已有同一版本的通过证据可直接复用。
2. 使用可丢弃的测试目录，包含中文和空格文件名、普通隐藏文件、空目录、开发依赖目录、macOS 元数据及指向目录外的符号链接。`.env` 仅使用虚构内容。规则以 [ArchiveFeature](../apps/macos/Sources/ArchiveFeature/README.md) 为准。
3. 另备大量小文件和较大文件，用于观察进度与取消。保存输出放在源目录之外，保留内容校验值。
4. 清除历史前备份本机 `Kaiwu/ArchiveLibrary.json`，只在允许清除测试记录的环境操作。网络切换先记录原配置，结束后恢复；容量测试使用独立测试卷。

## 原生交互

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| A1 | 选择目录、取消目录面板；分别用两种规则导出并解压；取消保存面板 | 取消面板不启动任务；内容与规则一致，源文件不变；空目录保留 |
| A2 | 将输出选在源目录内；选择已有同名 ZIP | 明确拒绝，已有文件内容保持不变；系统面板的覆盖确认不代表应用会覆盖 |
| A3 | 用大样本导出，观察阶段，在准备/压缩/保存时分别取消 | 界面可响应，准备/保存显示字节进度，压缩不虚构百分比；取消中不能重复启动；发布前取消不留目标半成品，已经发布的 ZIP 保留 |
| A4 | 保存书签，重复选择真实路径和目录别名；重命名源目录后再选书签；尝试失效目录；从历史再次打包、显示文件 | 同一目录只保留一条书签；有效目录可定位，失效有提示；再次打包恢复源目录与规则，导出时重新选目标；Finder 定位正确 |
| A5 | 关闭历史后成功导出；分别清除历史、在设置中清除历史与书签 | 关闭后不新增记录且原记录保留；两种清除范围正确，源文件和 ZIP 均不删除 |
| N1 | 关闭外部探测并诊断，再开启后主动诊断 | 分组和状态清楚；关闭时外部 DNS/HTTPS 标为未运行，本机配置检查保留；失败或未取得结果不能显示为通过 |
| N2 | 打开脱敏摘要预览，取消保存，再实际保存文本 | 取消不写文件；保存文本与预览一致；不出现真实服务名、地址、URL、路径、凭证或原始错误详情 |
| N3 | 在测试环境中逐项切换 VPN、多个网络服务、IPv6 回环代理及远端 PAC，再运行诊断 | 报告与配置一致；回环 TCP/PAC 结果准确，远端及带凭证/查询参数的 PAC 明确未请求；诊断不修改系统配置。用受控服务日志验证请求边界，不以界面文字代替网络证据 |
| S1 | 在设置与工具页分别修改规则、记录开关、测试地址、外部探测开关和控制器地址；退出并重启 | 两处偏好一致、重启后保留；Secret 不持久化 |
| S2 | 打开两个主窗口，分别选择页面、发起任务和修改设置；一个窗口更新历史，另一个重新进入打包页 | 导航与任务状态不串扰；共享偏好一致；历史重新进入后刷新，当前不要求实时同步列表 |
| S3 | 任务运行中跨页，立即返回并尝试再次启动；主动取消后重试；失败后重试 | 离页请求取消；旧任务退出前不可重复启动，旧结果不覆盖新任务；取消/错误反馈明确，任务结束后可重试 |

## 文件系统设备场景

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| D1 | 从本机向独立卷导出、从外部卷向本机导出，至少包含 ExFAT | 解压内容与源文件一致，取消和失败不遗留目标半成品；记录源/目标文件系统 |
| D2 | 在限额测试卷分别验证开始前空间不足，以及预检查后写入期间空间耗尽 | 报错能定位阶段；不误报成功、不损坏源文件或已有目标，界面恢复可用。记录是预检查拒绝还是实际写入失败，两者分别验收 |
| D3 | 按明确规模运行大量文件及大文件样本，记录文件数、总字节、耗时，并验证 ZIP 内容及取消 | 在本次样本范围内结果完整；超时必须明确反馈。默认任务预算 300 秒，成功样本不能扩展为任意规模性能保证 |

## 反馈格式

实际覆盖某项时可记录：`编号｜通过 / 失败 / 未测｜实际步骤与结果｜提交和环境｜证据或阻塞原因`。截图和日志先移除个人路径、网络配置及凭证；长期记录只保留必要事实。

发现缺陷时先保存可复现步骤，修复后重跑受影响用例和相关检查。只有路线图某一项所覆盖的场景均完成，才勾选对应里程碑；剩余限制继续保留。
