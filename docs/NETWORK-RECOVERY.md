# 网络诊断与恢复设计

设计参考本地网络恢复流程，仅提炼诊断与修复边界，未复制个人脚本或修改系统配置。运行时不依赖个人环境文件。

## 已落地

- 读取 DNS 配置（scutil）、默认路由与 1.1.1.1 出口（route）。
- 使用系统解析器（dscacheutil）查询测试域名，并与外部 DNS（dig / 223.5.5.5）对照。
- 读取 ifconfig，只将绑定 198.18.0.0/15 的 utun 标为候选；覆盖 198.18.* 和 198.19.*。
- 读取系统动态代理（scutil --proxy）；分别探测绕过代理的 HTTPS 与使用系统配置的 URLSession 路径。
- 提供建议与类型化修复计划，尚不执行系统修改。

## 与脚本的区别

脚本中的出口与默认接口不同、存在 Fake IP 或 utun，都可能属于正常 VPN/代理工作状态。界面显示证据，不直接宣布“发现残留”。命令失败、超时和空输出不会被当作检查通过。

脚本会批量设置 fallback DNS、删除预列出的路由、关闭本机系统代理并重试；原生实现不能未经核实地照搬。应用需先明确哪些设置由本应用或已退出的核心创建，保留原值并向用户展示具体变更。

现阶段未覆盖所有网络服务的独立代理配置、监听端口/PAC 健康检查、全量 IPv4/IPv6 路由表分析、核心进程占用和 DNS 缓存判定。没有把“诊断完成”当成“网络完全正常”。

## 修复执行流程（待实现）

1. 采集不可变快照：服务 ID、原 DNS/代理、路由、接口与核心生命周期。
2. 生成受限动作，解释预期影响并让用户选择；正常活动中的 VPN/TUN 不纳入自动清理。
3. 签名 `SMAppService` helper 经系统授权后接收类型化请求，不接受任意 shell、路径或命令。
4. helper 验证调用方代码签名、请求参数与当前状态；快照已过期则拒绝执行。
5. 记录操作结果，重新探测，再给出成功、部分恢复或失败状态。
6. 对持久修改保留回滚路径；退出应用仅恢复本应用拥有且未被其他程序改写的设置。

DNS cache flush 可以作为首个受限动作；关闭代理、写 DNS、删除路由要在上述快照与权限机制完成后逐项加入。
