# 平台客户端

每个平台的可独立构建工程放在 `apps/<platform>/`；目前只有 [macOS](macos/README.md)。

## 目录责任

- 平台目录包含该客户端的源码、测试、项目配置、原生集成、平台工具及构建脚本。
- 仓库根目录维护公共规范、文档、变更记录和 CI；`script/`、Makefile 提供统一入口。
- `docs/` 记录架构与流程，模块 README 维护当前实现状态，`changelog/` 记录对使用者或开发者有影响的变化。
- 其他平台按需新增，如 `apps/ios/`、`apps/windows/`、`apps/android/`；不创建空壳或预设未决定的技术栈。
- 跨平台共享代码仅在存在多个真实消费者时提取为独立包，并明确依赖方向，禁止直接引用其他平台的内部源码目录。

## 新增平台步骤

1. 新建平台目录和 README，说明工具链、运行方式、测试与平台限制。
2. 将平台配置、源码、测试、集成和缓存放在该平台目录内；敏感配置与产物必须被忽略。
3. 在平台的 `script/` 提供构建和验证命令，再按需要增加仓库入口与 Makefile target；保留已有入口的兼容性。
4. CI 使用独立的平台 job 与对应 runner；当前根检查入口覆盖 macOS 和全仓库文档，不宣称会自动构建未来平台。
5. 更新 [架构](../docs/ARCHITECTURE.md)、[文档地图](../docs/README.md)、[变更记录](../changelog/Unreleased.md)，并完成公开仓库审查。
